# 관리자 대시보드 (`admin.html`)

공개 사이트(`index.html`)와 분리된 글쓰기 화면입니다. 사이트 어디에도 링크하지 않고, 주소(`.../admin.html`)를 직접 열어 사용합니다. 접근 제어는 화면이 아니라 `firestore.rules`가 담당합니다.

## 처음 한 번 설정
1. 배포한 뒤 `admin.html`을 열고 Google로 로그인합니다. 관리자가 아니면 화면에 내 UID가 표시됩니다.
2. Firebase 콘솔 → Firestore → `admins` 컬렉션에 **문서 ID = 그 UID**, 필드 `enabled: true`로 문서를 만듭니다. (이미 등록돼 있다면 건너뜁니다.)
3. 규칙과 이력 조회 인덱스를 먼저 게시합니다: `npx firebase deploy --project takpilmo --only firestore:rules,firestore:indexes`
4. Firebase Authentication → Settings → 승인된 도메인에 사이트 도메인이 있는지 확인합니다.

## 글 쓰기
- 분류 `팁·따라하기`는 출처 없이 공개할 수 있고, 다른 분류는 출처가 1개 이상 필요합니다.
- 본문은 블록으로 구성합니다: 글, 이미지, 유튜브, 따라하기 단계, 팁·주의 박스, 링크 버튼. ↑↓로 순서를 바꿉니다.
- 이미지는 **https 주소**를 붙여넣습니다. 레포의 `assets/tips/`에 올리면 `https://<계정>.github.io/<레포>/assets/tips/파일명` 으로 쓸 수 있습니다.
- 유튜브는 링크만 붙여넣으면 됩니다. `?t=90` 으로 시작 시간을 지정할 수 있습니다.
- `보관`은 글을 숨기며 다시 공개할 수 있습니다. 목록과 편집 화면의 `글 삭제`는 확인 후 글과 서버 작업 초안을 함께 지웁니다. 삭제한 글은 목록에서 복원할 수 없고, 기존 수정 이력과 삭제 직전 내용은 관리자 기록으로 남습니다. 같은 브라우저에 남은 해당 글의 임시 사본도 정리합니다.
- 다른 탭에서 변경된 글은 삭제하지 않습니다. 최신 글을 다시 열어 확인하세요.
- 기존 글(`body`만 있는 글)은 그대로 보이고, 수정 화면에서 `블록으로 변환`을 누르면 블록 글로 바꿀 수 있습니다.

## 나중에 확장할 때
- 다른 사람이 글을 쓰게 하려면 `admins` 대신 역할(`role: editor | admin`)을 두고 규칙에서 쓰기/공개 권한을 나누는 방식이 자연스럽습니다.
- 이미지가 많아지면 Firebase Storage로 옮기고, 블록에는 URL만 저장되므로 기존 글은 그대로 둘 수 있습니다.

## 저장과 복구

- `저장`은 선택한 상태를 서버에 반영합니다. 공개 글에서는 `공개 변경 반영`으로 표시합니다.
- `초안 저장`은 미완성 본문도 보존합니다. 이미 공개한 글은 `articleDrafts`에 작업본을 저장해 공개 본문을 유지합니다. 다시 열 때 작업 초안을 이어 쓸지 선택할 수 있습니다.
- 서버 저장 중 입력을 계속해도 입력이 사라지지 않습니다. 이후 입력은 추가 미저장 변경으로 표시합니다.
- 브라우저 임시 보관은 서버 저장과 다릅니다. 새로고침 후 같은 계정·글에서 복구를 제안합니다. 새 글의 작성본은 `새 글 쓰기`에서 복구합니다. 공용 기기에서는 작성본을 내보내거나 명시적으로 나가기 전에 보관 여부를 확인하세요.
- `닫기`에서 미저장 변경 폐기를 확인하면 해당 탭의 임시 사본도 제거합니다. 다른 탭의 사본은 지우지 않습니다.
- 원문 내보내기는 JSON 파일을 다운로드합니다. 임시 보관 공간 부족이나 충돌 상황에서도 입력을 별도로 보존할 수 있습니다.
- 긴 입력은 잘라 저장하지 않습니다. 오류 위치에서 분량을 조정하세요. 기존 글 변환은 문단 경계로 나누며 안전하게 나눌 수 없으면 원문을 유지합니다.
- `되돌리기`는 최근 블록 삭제·단계 삭제·변환·버전 복원을 취소합니다. 모든 타이핑의 무제한 실행 취소는 아닙니다.
- `이전 버전`은 최근 50개 교체 전 본문을 표시합니다. 복원 후 저장해야 서버에 새 버전으로 반영됩니다. 이력 원본은 자동 삭제하지 않습니다.
- 두 탭에서 같은 글을 수정하면 먼저 저장한 버전과 충돌하는 저장은 거부됩니다. 현재 내용을 내보낸 뒤 목록 새로고침으로 최신 글을 확인하세요.
- 목록은 25개씩 불러옵니다. 검색·필터·정렬은 **불러온 글**을 대상으로 하며 더 불러오기로 범위를 넓힙니다.

## 권한과 제한

`articleDrafts`와 `adminHistory`는 관리자만 읽고 쓸 수 있습니다. 이력은 생성 후 수정·삭제할 수 없습니다. `admins/{uid}`의 `enabled:false`는 권한을 해제합니다. 기존 관리자 문서에 enabled 필드가 없으면 이전 동작과 호환해 허용합니다.

클라이언트는 블록 내부까지 검사하고, Firestore 규칙은 최상위 자료형·개수·상태·시각·접근 권한을 검사합니다. 규칙이 모든 배열 원소의 의미를 검증하는 것은 아닙니다. 관리자가 SDK를 직접 사용해 잘못된 블록을 쓰는 것을 완전히 막으려면 신뢰할 수 있는 서버 저장 경로가 추가로 필요합니다.

운영 적용·복원과 검증 결과는 `docs/admin-release.md`를 확인하세요.
