# 운영 안정화 기록과 대응 절차

## 범위

2026-09-24, main 9c47c9e에서 codex/production-hardening 작업 트리를 분리했다. 기존 codex/retention-mvp 미커밋 변경은 수정하지 않았다. GitHub Pages와 해시 주소를 유지하며 Cloudflare 연결, 운영 Sheets 수정, 테스트 글 공개는 제외했다.

## 확인한 범위와 측정

- 단위 검사 28개: 검색·저장·시트·정보 검증, 진행 중 조회 병합, 실패 재시도, 저장 충돌과 동일 내용 재시도.
- Chromium 회귀 30개 통과. 여기에는 1,000개/100편 검사와 정보 상세 뒤로가기 초점 복원이 포함된다.
- Firestore Emulator 5개 통과: 공개/초안 읽기, 비관리자 차단, 권한 생성 차단, 중첩 필드, 최대 허용 개수. 테스트 데이터는 demo 프로젝트 안에만 존재한다.
- 빌드 결과물 핵심 흐름은 Chromium·Firefox·WebKit에서 하위 경로 목록·상세·새로고침·관리자 로그인 입구·404를 확인했다.
- 기존 반응형 회귀가 320~1920px 대표 폭, 큰 글자·다크 모드의 가로 넘침을 검사한다. 모든 기기 조합을 검사하지 않았다.
- 로컬 Chromium, 가짜 응답, 단일 표본(자동화 대기 포함): 사이트 1,000개 목록 표시 228ms, 검색 입력 후 결과 확인 56ms, 정보 100편 목록 9ms. 실제 네트워크·저사양 단말의 성능 보장은 아니다.
- esbuild 결과 JS/CSS 전체 약 762 KiB 비압축, 전체 분할 파일 gzip 합 약 210 KiB. 최초 정적 import JS/CSS gzip 합 약 38 KiB이며 이후 정보 조회 SDK가 추가된다. 인증 모듈은 관리자 접근 시 로드된다. gzip은 로컬 계산값이며 실제 전송량은 서버 압축·캐시에 따라 다르다.
- npm audit --omit=dev 기준 운영 의존성 취약점 0개. 개발 도구의 모든 위험을 보장하는 수치가 아니다.

## 배포와 되돌리기

1. Firebase 프로젝트에 저장소의 rules 및 indexes를 배포한다. 관련 글 인덱스가 준비될 때까지 새 코드를 운영에 반영하지 않는다.
2. 저장소 Settings → Pages → Source를 GitHub Actions로 전환한다. main 루트 원본을 직접 배포하지 않는다.
3. PR 검사 후 main으로 병합한다. CI는 잠금 파일 설치 → lint → 단위 → Emulator → Chromium 회귀 → 빌드 → 세 브라우저 핵심 확인 → Pages artifact 순서다. 배포는 검사 성공에 종속된다.
4. 공개 URL에서 홈·사이트·정보 글·옛 주소 이동과 자산 로딩을 짧게 확인한다. 배포 완료 여부는 Actions 기록으로 확인한다.
5. 문제 발생 시 바로 이전의 정상 커밋을 되돌리는 PR을 만들고 동일 파이프라인으로 배포한다. 이미 생성된 정상 Pages 배포 run의 deploy job을 재실행하는 방법도 있으나 보관 artifact가 존재하는지 확인한다.
6. 최초 빌드 전환 이전 커밋으로 돌아갈 때는 Pages Source도 Deploy from a branch/main/root로 복구해야 한다. 과거 원본 커밋에는 빌드 workflow가 없기 때문이다.

코드 롤백은 Firestore 글을 되돌리지 않는다. 규칙은 콘솔 게시 이력이나 해당 Git 버전의 rules로 별도 복구한다. 문서 삭제 없이 공개 여부를 변경해 대응한다.

## 장애 진단과 권한 회수

- 사이트만 실패: 시트 API 권한·응답 형태를 확인한다. 화면의 시트 백업 안내 및 다시 연결을 사용한다. 백업 갱신은 검토 후 별도 커밋한다.
- 정보만 실패: 네트워크, Firestore 상태/할당량, 규칙, 인덱스 상태를 확인하고 해당 영역에서 재시도한다. 운영 글의 정적 사본이나 영구 오프라인 캐시는 없다.
- 관리자 저장 충돌: 입력을 복사해 보관한 뒤 목록을 새로 읽고 비교한다. 저장 결과 확인 실패 안내는 저장 자체의 실패와 다르므로 새 글을 만들지 않는다.
- 권한 회수: 콘솔에서 admins/{uid} 문서를 삭제한다. enabled:false만으로 회수되지 않는다. 변경 후 쓰기 권한은 서버 규칙이 차단한다.
- 로그인 실패: 승인 도메인과 팝업 차단 상태를 확인한다. 일반 Chrome/Edge에서 로그인한다. Firebase 웹 설정은 공개 설정이며 서비스 계정 키·비밀번호를 저장소에 넣지 않는다.
- 신규 추적·유료 모니터링을 추가하지 않았다. 브라우저 오류와 GitHub Actions 로그를 이용하고, 개인 입력이나 인증 토큰을 로그에 추가하지 않는다.

## 남은 제한

- 해시 글 주소의 검색 노출·SNS 카드가 글마다 독립되지 않는다. canonical·Open Graph는 홈 기준이다. 도메인 루트 robots 설정 때문에 다른 저장소를 변경하지 않았다.
- 제목·요약 부분 검색을 유지하기 위해 정보 목록은 공개 글 전체를 읽는다. 100편에서 확인했으며 훨씬 커지면 별도 검색 설계를 검토한다.
- 자동 브라우저 검사는 API 모의 응답을 사용한다. 실제 Google 로그인 및 운영 저장은 사용자 콘텐츠를 변경하지 않는 범위에서 별도로 확인해야 한다.
- 운영 Firebase 규칙·인덱스와 Pages 배포의 실제 완료 상태는 PR/최종 작업 보고를 따른다.
