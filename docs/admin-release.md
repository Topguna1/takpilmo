# 관리자 안정화 적용 기록

원본 검증 브랜치: `codex/admin-reliability` (`b1a18d6`). 운영 통합 브랜치: `codex/admin-production`, 기준 운영 커밋 `ee352fe`. 최신 운영 코드의 빌드·페이지네이션·데이터 검증을 유지하면서 관리자 변경만 통합했다.

## 구현한 범위

ZIP의 블록 글·관리자 페이지를 레포에 통합했다. 저장 중 입력 유실, 무통보 본문 잘림, 저장 후 목록 조회 실패에 따른 후속 저장 거부를 수정했다.

서버 저장을 트랜잭션으로 처리해 생성·최초 공개 시각을 보존하고 버전 충돌을 감지한다. 작업 ID를 재사용하는 동일 요청의 재시도는 새 버전을 만들지 않는다. 저장 응답 뒤의 입력은 미저장 변경으로 남는다.

미완성 초안, 사용자·글·탭별 브라우저 임시 보관, JSON 내보내기, 공개 글의 별도 작업 초안, 교체 전 본문의 원자적 이력 보관과 복원을 추가했다. 이력은 최근 50개를 표시하고 원본은 자동 삭제하지 않는다.

블록 접기·복제·중간 삽입, 일부 구조 변경 되돌리기, 순서 변경 후 초점 이동, 입력 오류·글자 수 표시, 이미지 URL 미리보기, 관련 사이트 선택, 상태 필터·제목 검색·정렬과 25개 단위 조회를 추가했다. 검색 범위는 화면에 명시한 불러온 글이다.

## 검증

- ESLint 통과.
- 운영 통합본 단위 테스트 37개 통과. 원본 검증본은 73개 통과.
- 운영 통합본 공개·관리자 E2E 37개, 배포 빌드 smoke 3개(Chromium/Firefox/WebKit) 통과.
- Firestore 에뮬레이터 규칙·실제 SDK 트랜잭션 테스트 10개 통과. 출처 10개·블록 60개·태그 8개 최대치의 실제 트랜잭션도 확인했다.
- 실제 SDK에서 생성 → 공개 → 작업 초안 → 공개 반영, 생성·공개 시각 보존, 이력 생성, 충돌 및 비관리자 차단, 동일 요청 재시도를 확인했다.
- 320·390·768·1440px 큰 글씨 편집 화면 검사. 320·1440px 스크린샷 확인.

## 운영 적용 전 남은 단계

2026-11-07 Firebase CLI 로그인과 운영 프로젝트 접근을 확인했다. 기존 운영 규칙·인덱스를 원본 작업 폴더의 `output/playwright/admin-review/production-before-20261107/`에 백업한 뒤 새 규칙과 인덱스를 배포했다. 배포 규칙과 로컬 일치 및 인덱스 3개 READY를 확인했다. 비로그인 공개 조회 200, 작업 초안·이력 조회 403을 확인했다. 정적 파일은 이 변경을 main에 병합한 뒤 CI and Pages 작업으로 배포한다. 실제 Google 계정으로 관리자 화면에서 시험 글을 작성하는 확인은 별도로 남아 있다.

1. 로컬 터미널에서 `npx firebase login`으로 운영 프로젝트 권한 계정에 로그인한다.
2. Firebase 콘솔에서 기존 규칙을 별도로 보관한다. 현재 운영 규칙이 레포와 동일하다고 가정하지 않는다.
3. `npx firebase deploy --project takpilmo --only firestore:rules,firestore:indexes`를 실행하고 인덱스 준비 완료를 확인한다.
4. 검증된 정적 파일을 사이트에 배포한다. 새 관리자 코드는 새 규칙을 먼저 필요로 한다.
5. 관리자 계정으로 시험 글 작성 → 초안 저장 → 재접속 → 수정 → 공개 → 보관 → 복원한다. 공개 글의 초안 저장이 공개 본문에 영향을 주지 않는지 확인한다.
6. 비로그인 창에서 공개 글만 읽히는지 확인하고 실제 이미지·임베드 가능한 영상도 확인한다.

## 복원

작업 전 수정된 추적 파일은 없었다. 변경 파일의 이전 내용과 새 파일 목록을 `output/playwright/admin-review/rollback-originals.zip`에 보관한다. 적용 직전 사용자의 변경이 있다면 먼저 별도 보관한다.

이전 파일은 백업 ZIP에서 해당 경로만 복원한다. 새 관리자 코드가 제공되는 동안 기존 규칙으로 먼저 되돌리면 저장이 거부되므로, 관리자 접근을 중단하거나 이전 정적 파일을 복원한 다음 규칙을 되돌린다. 실제 운영 규칙은 배포 직전 확보한 별도 사본을 사용한다.

Firestore 문서는 자동 삭제하거나 일괄 변환하지 않는다. 코드 복원은 저장된 글 내용을 이전 버전으로 돌리는 작업이 아니다. 본문 복원은 이력에서 확인해 실행한다.

## 후속 확장과 현재 한계

계획 8단계의 직접 이미지 업로드·파일 정리, 방문 조회수 수집, 서버 전체 텍스트 검색, 편집자 역할 분리는 구현하지 않았다. 저장소·비용·수집 기준 확정 후 진행하는 후속 범위다. 현재 이미지 URL 방식과 불러온 글의 상태별 개수를 제공한다.

로컬 임시 보관은 브라우저 저장 공간 한도의 영향을 받는다. 공간 부족 시 안내와 내보내기를 제공한다. 브라우저 기록 삭제나 다른 기기로 이동한 경우 복구되지 않는다. 같은 계정의 다른 탭에 남은 사본은 자동 삭제하지 않는다.

Firebase 운영 배포는 완료했다. 실제 관리자 브라우저의 로그인·시험 글 확인 및 후속 확장은 남아 있으므로 전체 계획 완료로 표시하지 않는다.
