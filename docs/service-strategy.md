# 딱필모 종합 서비스 개선 및 사업화 전략 계획서

기준일: 2026-10-31. 중·고등학생의 과제·탐구 문제에 집중한다. 1인·주 5~10시간 운영을 가정하며 재방문 검증 후 직접 만든 자료의 소액 판매를 시험한다.

이 문서는 승인된 전략의 실행 기준이다. 구현 현황과 아직 관찰하지 않은 사업 가설을 구분한다. 사용자 모집·28일 관찰·구매 실험은 실제로 수행하기 전까지 완료로 표시하지 않는다.

## 1. Executive Summary

목표는 자료를 정확하게 찾고 출처를 확인하며 다음 과제에서 다시 이용하는 경험이다. 핵심 전략은 저장한 사이트로 이어가기와 통계·문헌·발표 작업 안내다. 검색 정확도 → 신뢰 표시 → 홈 접근성 → 정보 품질 → 반복 사용 → 유료 검증 순서로 진행한다.

지금 제거할 것은 중복된 대형 소개, 카드 모서리 선택, 검증 근거와 불일치하는 정부 아이콘이다. 먼저 고칠 것은 ‘통계’와 ‘탐구’를 혼동하는 초성 검색이다. 첫 수익 실험은 무료 양식 실사용 후 원본 정리 팩 1종을 5,000원에 판매하는 것이다.

## 2. 서비스 현황 분석

현재 진입점은 index.html → js/hub/app.module.js다. 사이트는 Sheets, 원격 정보 글은 Firestore, 저장·최근 기록은 현재 브라우저에서 관리한다. 기존 사이트 키·저장 키·해시 링크를 유지한다.

대표 공개 주소: https://topguna1.github.io/takpilmo/ . 루트 주소는 별도 이전 서비스이므로 다른 저장소에서 안내·전환 작업이 필요하다.

최초 조사에서는 공개 162개와 로컬 백업 156개 사이의 차이를 관찰했다. 이번 구현에서는 2026-10-30T16:05:04.026Z 공개 응답의 원본 167행·상세정보 150건을 백업에 반영했다. 행 수는 중복 통합 후 사이트 수와 다르다. 기존 검증 날짜를 이번 날짜로 덮어쓰지 않는다.

사실: 검색·필터·상세·보관함·정보·관리자가 존재한다. 추론: 사이트를 익힌 사용자는 직접 방문할 수 있어 단순 링크 모음의 반복 가치는 약하다. 가설: 작업 안내와 저장 재사용을 연결하면 반복 가치가 생긴다. 방문자·유지율·매출·실제 월 운영비는 미측정이다.

## 5. UX/UI 및 정보 구조 개선안

홈 순서: 한 문장 가치 설명 → 검색 → 통계·문헌·발표 시작점 → 저장 최대 4개·최근 최대 3개 → 최신 원격 글 최대 3편 → 무료 양식·전체 분류·소개. 기록이 없으면 빈 이어가기 영역을 만들지 않는다.

초성 입력·한글 조합·키보드 자동완성을 보존한다. 검색에 상세 요약·주요 용도·사용 상황을 포함한다. 결과가 4개 미만이고 학교급 조건이 있으면 검색어·다른 필터를 유지한 학교급 해제 링크를 제공한다.

학교급은 추천 대상이며 가입 가능 연령이 아니다. KOSIS의 공개 통계 탐색은 중학생 과제 활용 대상으로 보완하되 다른 사이트의 대상을 일괄 확대하지 않는다. 핵심 20개의 실제 과제 수행 검수는 별도 기록한다.

운영 주체 표시에는 공식 출처와 확인일을 요구한다. 공공 필터는 검증된 government/public만 포함한다. 기존 isGov만 있는 항목은 포함하지 않는다. 공공 운영은 정보 정확성 보증이 아니다.

신규 회원·결제·추천 API는 만들지 않는다. 기본 작업 안내는 기존 정보 글 인터페이스를 이용하는 정적 저작물로 제공하여 원격 글 장애와 독립적으로 연다. 기존 원격 글의 공개·비공개 정책은 그대로 적용한다. 홈 조회만 limit(3), 전체 목록 검색은 전체 공개 글을 대상으로 유지한다. 30편 초과 시 커서 페이지네이션을 별도 진행한다.

## 6. 사용자 가치 및 차별화 전략

초기 대상은 자료 종류·검색 장소·출처 확인 방법을 모르는 중·고등학생이다. 교사·보호자는 검수·소개 협력자로 둔다. 핵심 가치 제안: 과제 자료를 어디서 찾고 무엇을 확인해야 하는지 알려주며 다음 과제에서도 바로 꺼내 쓰게 하는 출발점.

통계 안내는 표 제목·기관·시점·단위·주소를, 문헌 안내는 질문·초록·원문 조건을, 발표 안내는 주장·근거·이미지 조건을 다룬다. 사이트 수나 AI 기능으로 차별화하지 않는다.

상품은 탐구 질문·자료 비교·출처 기록·발표 확인·가상 예시를 담은 원본 팩 1종, 시험 가격 5,000원이다. 기존 사이트·정보 글·기본 양식은 무료로 유지한다. 현재 무료 HTML·Markdown 시제품만 제공한다. 검증 전에 유료 상품이나 가짜 구매 버튼을 노출하지 않는다.

무료 시제품 10명 중 5명 실제 사용 → 유료본 제작 → 외부 판매 채널의 상품 심사·거래 조건 충족 → 적격 상세 방문 100회에서 3건 구매를 시험 기준으로 삼는다. 노출 부족은 판단 보류, 100회에 구매 0건이면 추가 상품 제작 중단이다. 보상·할인 구매는 일반 구매와 분리한다.

월 판매액 = 방문자 × 상품 상세 방문율 × 구매율 × 5,000원. 실제 수익 예측이 아닌 민감도 계산이다.

| 가정 | 방문자 | 상세 방문율 | 구매율 | 판매액 | 비용 가정 적용 잔액 |
|---|---:|---:|---:|---:|---:|
| 보수적 | 1,000 | 10% | 1% | 5,000 | -26,500 |
| 기준 | 5,000 | 10% | 2% | 50,000 | 5,000 |
| 낙관적 | 10,000 | 15% | 3% | 225,000 | 127,500 |

잔액 = 판매액 × 70% - 30,000원. 수수료 25%·환불 충당 5%·고정비 3만원은 확인되지 않은 계산 가정이며 인건비·소득 관련 세금 전이다. 시간당 2만원의 기회비용이면 월 20시간은 40만원이다.

판매 전 GitHub Pages 상업 운영 정책, 저작권·외부 자료 권리, 미성년자 거래, 상품 미리보기·환불·청약철회, 판매자 고지·세무 요건을 점검한다. 외부 판매 URL이 확정되기 전 자체 결제를 만들지 않는다.

## 10. 개발 우선순위 및 단계별 실행 로드맵

개발·검증 42h + 조사·콘텐츠·운영 42h + 예비 6h = 90h. 평균 주 7.5h로 12주, 주 5h이면 약 18주다. 아래 시간은 앞의 개별 추정과 중복 합산하지 않는다.

| 단계 | 작업·목적 | 공수 | 완료·다음 단계 조건 |
|---|---|---|---|
| 1 / 1~2주 | 검색·신뢰 오류·홈·설정 정리 | 개발10+검수4 | 검색10과제·첫 화면 검색·표시 일치 |
| 2 / 3~5주 | 핵심20개·백업·작업 안내3개 | 개발10+조사10 | 조건 또는 미확인 이유·출처·날짜, 관찰5명 중4명 성공 |
| 3 / 6~9주 | 이어가기·반복 관찰 | 개발10+운영12 | 15명 중5명이 28일 내 다른 주에 작업 |
| 4 / 10~11주 시작 | 무료 시제품·원본 상품1종·외부 판매 | 개발6+제작12 | 무료10명 중5명 사용, 적격100회에3건 구매 |
| 5 / 12주 이후 | 실패 경로·제한 조회·운영 정착 | 개발6+운영4 | 주2h 이내 운영·핵심 성공 유지 |

관찰 기간·노출 확보는 개발 속도로 단축하지 않는다. 조건 미충족 시 다음 단계 확장을 중단한다. 정적 URL·다기기 동기화·AI·자체 결제는 초기 범위 밖이다. 배포는 작은 단위로 나누며 기존 저장 키·URL을 보존한다. 호스팅 변경 시 로컬 저장 이전 절차를 먼저 마련한다.

## 11. 성과 측정 KPI 및 검증 방법

관찰·주간 기록·외부 판매 집계를 사용한다. 분석 인프라와 무단 행동 수집을 추가하지 않는다. 표본 결과를 전체 DAU·WAU로 표시하지 않는다.

- 탐색 성공: 적합한 사이트와 조건을 설명하며 자료 탐색 시작, 5명 중4명.
- 첫 유용한 결과: 대표 과제 중앙값 60초를 가설 목표로 측정.
- 반복 사용: 15명 중5명, 28일 내 다른 주의 실제 과제.
- 저장 재사용: 저장자 중 다른 날 다시 연 인원/분모 함께 기록.
- 안내 효과: 읽기와 실제 자료 확보를 구분.
- 데이터 충실도: 핵심20개 값 또는 미확인 이유 관리 100%.
- 운영 부담: 초기 제작 뒤 주2h 이내.
- 판매: 적격 상세100회·구매3건, 환불·문의 이유와 인건비 포함 경제성 기록.

동의 절차 후 가명 ID를 사용하되 익명이라고 단정하지 않는다. 신원표는 분리하고 조사 종료90일 내 원자료 삭제, 집계만 보관한다. 학교·성적·개인 검색어·과제 원문은 수집하지 않는다.

기능 검증: 완성형·초성·IME·조건해제·검증 필터·저장 새로고침·저장 거부·API/백업 실패·정보 장애·관리자 제한·320/390/768/1440px·확대·구주소·뒤로가기. 실제 검증 결과는 service-strategy-implementation.md에 기록한다.

## 12. 위험 요소와 대응 방안

과제의 계절성은 기회가 있었던 주와 함께 해석한다. 북마크 대체 위험에는 작업 안내의 실제 효용으로 대응한다. 변동 조건은30일·일반 설명90일 재검수 기준으로 관리한다. 주간 운영2h 초과 시 신규 등록을 중단한다. 백업 생성일을 표시하되 생성일을 개별 사실의 재검증일로 혼동하지 않는다.

권리 미확인 자료는 상품에 넣지 않는다. 만14세 미만의 동의가 필요한 개인정보 처리에는 법정대리인 절차를 확인한다. 공공기관은 정확성 보증이 아니며, 잘못된 정보는 공식 근거로 정정한다. 원격 정보의 비공개 회수를 방해하는 영구 캐시를 추가하지 않는다.
