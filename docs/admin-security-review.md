# 관리자 접근 보안 점검

## 판단

대시보드 HTML/JavaScript와 로그인 화면은 공개 정적 파일이다. 주소를 알아내거나 개발자 도구에서 버튼을 만드는 것은 가능하지만, 글·작업 초안·이력의 권한은 Firestore 서버 규칙에서 별도로 검사한다. 점검한 범위에서는 비관리자가 권한을 획득하거나 비공개 데이터를 읽고 수정하는 우회 경로를 발견하지 못했다. 침투 가능성을 0%라고 보장하거나 모든 공격을 검사했다는 뜻은 아니다.

## 확인한 범위

- 비로그인, 일반 계정, 관리자라는 임의 역할 claim을 가진 비관리자 계정의 문서 접근을 에뮬레이터에서 검사했다.
- 관리자 목록 열람, 관리자 문서 생성/변조, 초안 조회, 작업 초안·이력 조회/쓰기, 글 생성은 거부됐다. 권한은 UI나 임의 role claim이 아니라 admins/{인증된 UID} 문서로 결정된다.
- disabled 관리자의 저장이 거부된다. 현재 운영에는 명시적으로 enabled:true인 관리자 문서 1개가 있다. 레거시 호환을 위해 enabled가 없는 관리자 문서도 허용하는 규칙이므로 관리자 추가/해제는 Firebase 콘솔에서 신중하게 관리해야 한다. 일반 계정은 이 컬렉션을 수정할 수 없다.
- 실제 운영 REST API에서 비로그인의 관리자 목록·작업 초안·이력 조회는 403, 위조한 토큰은 401로 차단됐다. 실제 운영에 공격용 문서를 작성하거나 새 계정을 생성하지 않았다.
- 운영 규칙과 레포 일치는 이전 배포 확인 자료에 기록되어 있고 이번 권한 검증도 그 규칙을 사용한다.
- 프로젝트 IAM에 allUsers/allAuthenticatedUsers에 대한 공개 권한 부여는 발견하지 못했다. 모든 개별 계정의 적절성이나 조직 상속 정책을 전수 감사한 것은 아니다.
- 공개 웹 API 키는 Firebase 관련 API 제한이 설정되어 있고 웹 referrer 제한은 없다. 일반인이 API 키를 아는 것만으로 관리자 권한을 얻지는 않는다. 키의 API 허용 목록에 generativelanguage.googleapis.com은 없다.
- 입력 내용은 HTML escape를 거쳐 표시되고, 링크와 이미지 URL 및 YouTube 호스트를 검사한다. 기존 렌더러 테스트에서 스크립트·이벤트 속성·실행 URL 방어를 확인한다. 모든 브라우저/SDK 취약점을 검사한 것은 아니다.

## 이번에 보완한 부분

계정을 바꾸는 동안 이전 관리자 확인 응답이나 저장 완료 응답이 뒤늦게 도착해 새 세션 화면에 적용될 수 있는 UI 상태 경합을 보완했다. 계정 변경 즉시 편집 화면·글 목록·이력 상태를 비우고 이전 세션의 응답은 무시한다. 이 문제는 Firestore 서버 권한을 우회하는 경로와는 별개지만, 같은 브라우저에서 계정을 전환할 때의 표시를 보호한다.

## 남는 위험과 권장 사항

1. 관리자 Google 계정 또는 프로젝트 소유 계정이 탈취되면 정상 권한으로 글이 변경될 수 있다. 패스키/2단계 인증과 프로젝트 구성원 관리가 중요하다. 계정의 실제 2단계 인증 설정은 이번 점검에서 확인하지 않았다.
2. Firebase App Check 서비스 조회 응답에는 enforcementMode가 명시되지 않았다. App Check 토큰 없는 REST 요청이 접근 가능한 상태이므로, App Check 강제로 모든 API 남용이 차단된 상태라고 판단하지 않는다. 공개 글 대량 조회에 따른 비용·할당량 남용은 관리자 권한 침해와 별개로 남는다. App Check와 예산 알림 도입을 권장하되, 현재 클라이언트에 공급자 설정 없이 강제하면 정상 사용도 차단되므로 이번에 강제 설정을 바꾸지 않았다.
3. API 키에 referrer 제한을 추가하려면 운영 도메인·localhost·로그인 흐름을 함께 검증해야 한다. 이 제한만으로 접근 권한을 보호할 수는 없다.
4. 관리자가 직접 SDK로 잘못된 블록을 쓰는 것까지 서버가 완전히 검증하지 않는다. 현재 규칙은 블록 개수와 최상위 필드를 검사하고, 상세 블록 검증은 에디터에서 한다. 관리자 계정 탈취에 대비한 추가 검증이 필요하면 서버 저장 경로를 도입해야 한다.
5. 브라우저 임시 보관은 기기에 남는다. 공용 기기에서 같은 Google 계정/브라우저 프로필을 공유하지 않는 것이 좋다.

## 공식 근거

- Firebase API 키는 프로젝트 식별용이며 권한은 Security Rules/IAM 등이 담당한다: https://firebase.google.com/docs/projects/api-keys
- App Check는 일부 API 남용을 줄이는 추가 계층이며 모든 남용 차단을 보장하지 않는다: https://firebase.google.com/docs/app-check

검증 요약과 비밀값을 제외한 운영 설정 요약은 로컬 output/admin-security/에 보관한다. 인증 토큰이나 OAuth 인증 코드는 보고서에 저장하지 않는다.
